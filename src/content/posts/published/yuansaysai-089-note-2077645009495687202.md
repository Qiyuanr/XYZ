更新 ChatGPT 之后，不少人遇到的第一个问题不是"GPT-5.6 有多强"，而是：

我的 Codex 去哪了？Chat、Work、Codex 三个入口，到底点哪个？Sol、Terra、Luna 到底怎么选？

先说结论：

Codex 没有消失，也没有变成普通聊天。

OpenAI 只是把原来的 Codex App 和 ChatGPT 桌面端合并成了一个应用。现在同一个 ChatGPT 桌面 App 里，有三个不同岗位：

- Chat 负责讨论
- Work 负责交付成果
- Codex 负责操作项目

而 GPT-5.6 带来了三个模型（Sol / Terra / Luna）和多档推理强度。选错模型和推理档位，同样的任务花费可能差好几倍。

理解三个入口和模型选择策略，比研究零散参数更重要。

---

## 一、这次到底合并了什么？

以前，你可能要分别打开 ChatGPT 和 Codex。

现在，更新后的 ChatGPT 桌面 App 把 Chat、Work 和 Codex 放到了一起。

如果你以前使用 Codex App，正常更新后，它会直接变成新的 ChatGPT 桌面 App。原有的 Codex 项目和任务会继续保留，也可以继续把 Codex 设为默认首页。

> 如果你以前用的是旧版 ChatGPT 桌面端，新 App 会以"ChatGPT"的名字安装，旧的会改名为"ChatGPT Classic"，两个可以共存，不需要迁移。

所以，这次合并不是"Codex 被取消"，而是：

> 原来分开的聊天助手和执行助手，现在搬进了同一个办公室。

合并的是入口、账号和部分工作能力，不是把三种工作方式揉成一种。

---

## 二、合并后带来了四个实际影响

## 影响 1：以后不用在两个 App 之间来回切

你可以在一个桌面 App 里完成：

- 和 Chat 讨论想法
- 让 Work 查资料、做 PPT
- 让 Codex 修改本地项目

更关键的是：Codex 页面的侧栏直接内置了"聊天"入口，点击后右侧会打开一个完整的 ChatGPT 对话窗口。 左边跑 Codex 任务，右边用 Chat 聊方案，同一个屏幕里无缝切换。你甚至能看到原来 ChatGPT 的对话历史，聊到一半的上下文直接接上，不用从零开始解释背景。

这减少了复制提示词、重复上传资料和反复解释背景的成本。

## 影响 2：普通人也必须学会"分派任务"

以前很多人把所有问题都扔进 Chat。

合并后，错误入口会直接影响效率。

例如，你想做一份竞品分析报告：

- 用 Chat，它会和你讨论、给出文字建议；
- 用 Work，它会查资料、分析文件并交付报告；
- 用 Codex，它更擅长处理网站、代码、数据文件和自动化流程。

同一句需求，入口选错了，得到的结果就会完全不同。

## 影响 3：Agent 额度开始共享

这是合并后最容易踩的坑。

根据 OpenAI 官方说明，Codex、ChatGPT Work、ChatGPT for Excel 和 Workspace Agents 共享同一套 Agent 使用额度和 Credits。

也就是说：

你在 Codex 里连续运行大型任务，可能会影响 Work 还能用多少；反过来也一样。

但普通 Chat 不在这组共享 Agent 额度里。日常问答、聊天和普通内容生成，走的是 ChatGPT 自己的聊天限制（比如 Plus 用户每 3 小时 160 条 Instant 消息），不会因为应用合并就消耗 Codex 任务额度。

需要记住：

> Chat 看聊天额度，Work 和 Codex 看 Agent 额度。

不同模型消耗 Agent 额度的速度也不同。以下是基于官方费率换算的每百万 Token Credit 消耗参考：

![原文配图](https://pbs.twimg.com/media/HNVDukybQAAIpBi.jpg)

> Sol 的输出价格是 Terra 的 2 倍、Luna 的 5 倍。同样一个任务，选错模型，消耗可能差 2-5 倍。

## 影响 4：不同入口的记录并没有完全打通

根据官方文档确认：

- 普通 Chat 对话可以在 ChatGPT 网页和桌面端同步。
- Work 对话：上线初期，云端 Work 对话不会出现在桌面 Work 中；桌面 Work 的线程和本地文件只保存在当前电脑。
- Codex 不是网页或手机上的独立可选模式。手机端主要通过 Remote 入口查看和继续受支持的桌面 Codex 任务。

所以"合并成一个 App"，不等于所有聊天、文件和任务已经完全互通。

## 三、Chat、Work、Codex 到底怎么选？

不要先想模型，先看你最后想得到什么。

## 只想得到一个回答：用 Chat

适合：

- 问一个问题
- 润色一段话
- 翻译内容
- 头脑风暴
- 讨论方案
- 快速写文案
- 帮你判断方向

Chat 的重点是交流。

例如：

> 我准备做一个 AI 课程，请帮我分析目标用户和内容结构。

这种需求先用 Chat，因为你还在想清楚问题。

## 想得到一份成品：用 Work

适合：

- 调研一个行业
- 分析多份资料
- 制作文档、表格或 PPT
- 生成完整报告
- 创建网站或仪表盘
- 从多个工具中收集信息
- 执行需要几十分钟甚至更久的任务

Work 的重点不是陪你聊，而是交付成果。它可以连接 Slack、Gmail、Google Drive 等外部工具，自动拉取资料并整合成可交付的文件。

例如：

> 阅读这 5 份用户访谈，找出主要痛点，制作一份带图表的产品分析 PPT。

这就是典型的 Work 任务。

使用 Work 时，最好先让它进入 Plan 模式。让它先说明：

1. 准备读取哪些资料；
1. 准备如何分析；
1. 最后会交付什么；
1. 哪些地方需要你确认。

确认计划后再开始执行，可以避免它跑了半天却做错方向。

## 想让 AI 操作文件或项目：用 Codex

适合：

- 编写和修改代码
- 处理整个项目文件夹
- 查找程序错误
- 运行测试
- 审查代码改动
- 操作 Git 仓库
- 调试网页
- 批量处理本地文件
- 使用终端和开发工具

Codex 的重点是执行。

例如：

> 检查这个网站为什么手机端错位，修复问题，运行测试，然后把修改内容列给我确认。

这类任务需要查看本地文件、修改代码并验证结果，应该交给 Codex。

最简单的判断方法是：

> 要答案用 Chat，要成品用 Work，要动文件用 Codex。

## 四、GPT-5.6 三个模型应该在哪里选？

这里是很多教程没有说清楚的地方。

## 先搞清楚：模型和推理强度是两件事

GPT-5.6 系列里，你需要选择两样东西：

第一，选模型（能力档）：

- Sol：旗舰，最强推理和执行能力
- Terra：均衡，性能对标上一代 GPT-5.5，但价格只有一半
- Luna：最便宜最快，适合批量轻量任务

第二，选推理强度（投入多少算力）：

每个模型都可以独立调节推理强度，从低到高大致分为几档：

- 低档（快速响应）：适合简单问答、快速修改、数据提取
- 中档（默认，速度和推理深度平衡）：适合日常大部分任务
- 高档（更深推理）：适合复杂分析、多步骤任务
- 更高档（极深推理）：适合高难度问题、代码审查
- 最高档（最大推理深度）：适合最难的问题，需要反复验证

> "多智能体并行"（Codex Ultra 模式）不是推理强度的参数。它是 Codex 产品中的特殊模式（默认 4 个子智能体协作，最高 16 个），在 Codex 桌面 App 里通过界面切换，不是你可以在配置文件或 API 里设置的值。

> 关键原则：优先选能完成任务的最低推理强度。不必所有任务都开最高档，否则白白增加等待时间和额度消耗。

## 在普通 Chat 中

普通 Chat 的模型选择器里，你看到的不是 Sol/Terra/Luna，而是推理档位：

![原文配图](https://pbs.twimg.com/media/HNVD2JGbEAArA6z.jpg)

普通 Chat 里不能直接选择 Terra 和 Luna。 不要到处寻找"Luna 按钮"或"Terra 按钮"，它们本来就不在标准聊天的模型选择器中。

各套餐可用情况：

![原文配图](https://pbs.twimg.com/media/HNVD3G2aMAALyX6.jpg)

> 注意：Go 用户可以在聊天输入框点 + 然后选 Thinking 来获得类似推理体验，但这个选项用的不是 GPT-5.6 Sol，每 5 小时限 10 条。

日常建议：

- 普通问答：Instant
- 需要认真分析：Medium
- 多步骤难题：High
- 极少数关键难题：Extra High
- 长时间高难任务：Pro（仅 Pro 套餐）

## 在 Work 和 Codex 中

符合条件的 Plus、Pro、Business 和 Enterprise 用户，可以在 Work 和 Codex 中选择 Sol、Terra 和 Luna。

Codex 的 Free 和 Go 用户可以使用 Terra。

三个模型的 API 定价（每百万 Token）：

![原文配图](https://pbs.twimg.com/media/HNVD1tOaIAE_9BG.jpg)

> Sol Ultra 模式在 Terminal-Bench 2.1 上取得 91.9%，但会消耗更多推理 Token，同一个价格下花费更高。

可以把它们理解为三种员工：

- Luna：执行速度快，适合整理、提取、批处理；
- Terra：能力和消耗均衡，适合大部分日常工作；
- Sol：能力最强，适合复杂研究、关键审查和疑难任务。

小白最合理的默认配置：

> Work 和 Codex 默认用 Terra，简单批量任务换 Luna，关键任务最后再换 Sol。

不要把 Sol 设成所有任务的默认模型。

Sol 处理复杂任务确实更强，但任务越复杂、上下文越长、运行时间越久，消耗的共享 Agent 额度通常也越多。

## 五、合并后的正确工作流

## 场景 1：写一篇重要文章

第一步，用 Chat 讨论：

> 我要给零基础用户写一篇 GPT-5.6 教程。请帮我确定读者最关心的 5 个问题和文章主线。

第二步，方向确定后，进入 Work：

> 搜集公开资料和我提供的参考文章，完成一篇可发布的教程，并附上信息来源。

第三步，先用 Terra 完成初稿。

第四步，文章涉及重要事实时，再用 Sol 做一次事实检查和逻辑审查。

不要一开始就让 Sol 从零搜集、写作、改稿、排版。这样最容易快速消耗额度。

## 场景 2：制作一份竞品分析 PPT

不要在 Chat 里一句句生成 PPT 内容。

直接进入 Work，上传竞品资料、公司模板和已有数据，然后说：

> 先制定分析计划。确认后，比较 5 个竞品的定位、功能、价格和用户评价，最后按照公司模板生成 15 页汇报 PPT。

普通整理先用 Terra。

如果最后需要做重要战略判断，再让 Sol 检查结论是否站得住。

## 场景 3：修改一个网站

进入 Codex，打开网站所在的项目文件夹。

先说：

> 先检查项目结构并复现问题，不要立即修改。找到原因后给我一个修复计划。

确认后再让它修改、测试和检查移动端。

如果只是修改按钮颜色、替换文字，Terra 甚至 Luna 就够了。

如果涉及支付系统、数据库迁移或复杂架构，再切换 Sol。

## 六、怎么避免额度消耗过快？

只需要遵守五条。

第一，普通问题留在 Chat。 不要为了问一句话启动 Work 或 Codex。

第二，Work 和 Codex 默认使用 Terra。 不要默认 Sol。一个典型的 Agent 编码任务（80 万输入 + 6 万输出 Token），Terra 约 2.9 美元，Sol 约 5.8 美元，Luna 约 1.16 美元。如果 80% 的输入命中缓存，Terra 还能降到约 1.46 美元。

第三，大任务先 Plan 再执行。 方向错一次，比模型选贵一次更浪费额度。

第四，一个任务只保留相关文件和上下文。 不要把整个硬盘、几十个无关附件和几个月的聊天历史全部交给模型。

第五，Chat + Codex 搭配用，讨论和执行分开烧额度。 这是合并后最实用的工作流。

以前 ChatGPT 和 Codex 是两个独立 App，想一边聊方案一边写代码，得在两个窗口之间反复切换、复制粘贴，非常痛苦。

合并后，Codex 页面的侧栏里直接新增了"聊天"入口。 点开就能在右侧打开一个完整的 ChatGPT 对话窗口——左边跑 Codex 任务，右边用 Chat 聊方案，同一个屏幕、同一个 App，不需要切窗口。

![原文配图](https://pbs.twimg.com/media/HNVEk6PbgAAOUiV.jpg)

你甚至能看到原来 ChatGPT 的对话历史，聊到一半的上下文可以直接接上，不用从零开始解释背景。

正确做法是：

> 先在右侧 Chat 窗口里把需求聊清楚、把方案迭代好，再把最终方案直接丢给左侧 Codex 窗口执行。

为什么这样省？因为 Chat 走的是聊天额度（比如 Plus 用户每 3 小时 160 条 Instant），不消耗 Agent Credits。而 Codex 每跑一轮都在烧共享 Agent 额度。

如果你直接在 Codex 里反复改需求、来回讨论，每一轮对话都在消耗 Agent Credits——哪怕你只是在问"你觉得这个方案怎么样"。

以前两个 App 的时候，这个技巧理论上也能做，但体验太差：切窗口、等加载、复制上下文，大部分人坚持不了两次就放弃了。现在合并到一个 App 里，Codex 侧栏直接内置了聊天入口，左侧跑任务、右侧聊方案，这个工作流终于从"理论上可行"变成了"日常顺手就能做"。

举个例子，你要重构一个模块：

1. 在右侧 Chat 窗口里讨论（消耗聊天额度，不花 Agent Credits）：

> 我有一个 Express + MongoDB 的认证模块，想重构成支持 OAuth2。帮我分析现有代码的问题，列出重构步骤，先不要写代码。

1. 在右侧 Chat 窗口里继续迭代方案（还是聊天额度）：

> 第二步用 JWT 不用 session，理由是什么？第三步的数据库迁移有没有风险？

1. 方案确定后，直接复制到左侧 Codex 窗口（现在才开始花 Agent Credits）：

> 按照以下方案重构认证模块：1. 替换 session 为 JWT；2. 新增 OAuth2 provider；3. 迁移 users 表新增 oauth_id 字段。先跑测试确认当前状态，再逐步修改。

这样 Codex 一上来就知道干什么，不需要在 Agent 模式里浪费 Credits 来回讨论。讨论阶段零 Agent 消耗，执行阶段每一 Credit 都花在刀刃上。

> 原则：Chat 负责想清楚，Codex 负责做到位。合并后 Codex 侧栏直接内置聊天入口，左边跑任务右边聊方案，终于能像同事一样坐在一起办公了。

真正省额度的关键不是少用 AI，而是：

> 讨论、交付、执行，各走各的入口。讨论用聊天额度，执行才花 Agent 额度。

## 七、更新后常见问题

## 我的 Codex 项目会消失吗？

不会。官方确认，已有 Codex 任务和项目在更新后继续保留。如果你原来使用 Codex App，更新后默认也会先进入 Codex。

## 为什么我看不到 Work？

Work 仍在分批开放。先更新桌面 App，并确认登录的是正确账号。桌面端所有套餐（包括 Free）都能用 Work；网页和手机端正在向付费套餐推送（Pro、Enterprise、Edu 优先，Plus 和 Business 随后）。

## 为什么我看不到 Terra 和 Luna？

标准 Chat 中本来就不能选择它们。需要进入 Work 或 Codex，并且你的套餐必须支持。如果 Codex 里也看不到，检查客户端版本：桌面端 Codex 模式需要 26.707.30751 以上，CLI 需要 0.144.0 以上。

## 普通手机聊天会消耗 Codex 额度吗？

不会。普通 Chat 有自己的聊天和推理限制，走的是 ChatGPT 的消息额度（如 Plus 用户每 3 小时 160 条 Instant）。共享 Agent 额度主要用于 Codex、Work 以及其他受支持的 Agent 功能。

## 合并后还需要单独下载 Codex 吗？

不需要。新用户直接下载新的 ChatGPT 桌面 App 即可。Codex 已经成为其中一个入口，不再需要为了桌面 Codex 另外安装一套独立应用。

## ChatGPT Classic 和新 App 有什么区别？

新 App 包含 Chat、Work 和 Codex 三个模式，新功能优先在这里上线。ChatGPT Classic 是旧版桌面端，会继续收到模型更新和安全补丁，但新的 Agent 功能（如 Work）只在新的 ChatGPT App 中提供。

## 最后给小白一张使用口诀

入口选择：

> 问问题，开 Chat。

> 做成品，开 Work。

> 动项目，开 Codex。

模型选择：

> 默认 Terra，简单 Luna，关键才用 Sol。

> 推理强度先默认，不够再加，别一上来就拉满。

省钱五条：

> 普通问题留 Chat。

> Codex 侧栏点"聊天"，左边跑任务右边聊方案，讨论不花 Agent 额度。

> 大任务先 Plan 再执行。

> 一个任务只留相关上下文。

> 同一份上下文反复提问，善用缓存省 90%。

GPT-5.6 最重要的升级，不只是模型更强。

真正的变化是：ChatGPT 开始从一个回答问题的聊天框，变成一个能讨论、交付和执行的完整工作台。

先学会分工，再追求最强模型。
