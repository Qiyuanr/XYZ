Hi，朋友们，好久不见👋。

最近好几天没更新呢，是因为去玩一个新的Codex插件了。就是最近在𝕏上很火的ChatCut。测试了几个不同的示例，都挺有意思的。比方说这个图书带货视频，就是用ChatCut一键生成的。

测完以后一个很直观的体感是，这个插件非常适合做图书带货。

所以，今天我们就来聊聊如何用Codex+ChatCut，实现自动化图书带货。

![原文配图](https://pbs.twimg.com/media/HNfqY28awAAgL7a.jpg)

## 为什么是图书带货

其实做带货变现，很多人第一反应是去做那些爆款品类，什么美妆、零食、日用品。但说实话，这些品类竞争太激烈了，而且售后问题特别多。

图书这个品类就不一样。

![原文配图](https://pbs.twimg.com/media/HNftjeZaUAAoxvE.jpg)

我这段时间研究了一下，发现图书带货有三个很明显的机会点。

第一个机会点，是用户人群。

视频号上聚集了不少消费力强的中青年和下沉银发人群。这些人对个人成长、历史社科、家庭教育这类图书都有稳定需求。你想想，一个35岁的职场人，晚上刷视频号看到一本讲职场沟通的书，他会不会下单？概率很大的。

而且这些人群的付费意愿比其他平台更高，因为他们有阅读习惯，也愿意为知识付费。

第二个机会点，是内容质量参差。

我去视频号搜了一圈图书推荐的内容，说实话，很多视频的制作质量和文案水平都很一般。要么是照着书籍简介念一遍，要么是画面乱七八糟，要么是节奏拖沓。

这反而给我们留了空间。只要你的文案梳理清楚，节奏舒服，画面干净，就大概率能脱颖而出。

第三个机会点，是门槛相对友好。

视频号的图书带货，0粉就能开通橱窗带货。挂车需要1000粉，但按照视频号的流量来看，不需要几个视频就能达到，而且还可以通过其他渠道涨粉。这个门槛比抖音、小红书要友好多了。

还有一点特别重要，图书这个品类的售后率很低，基本不超过5%。你想想，买一本书的人，基本不会退货。而且所有的发货、物流、客服问题都不用你管，你只要做好内容，到手的都是净利润。

所以你看，图书带货这个方向，用户需求稳定、内容质量参差、门槛友好、售后率低，是不是很适合新朋友入局搞钱？

## 需要提前准备什么

说了这么多，那具体要怎么做呢？其实也不复杂，但有几个工具是必须提前准备好的。

1. ChatCut插件

这个是最核心的工具。ChatCut是Codex的一个新剪辑插件，它能在Codex应用内直接打开一个完整的视频编辑器，让你和AI助手一起协作剪辑。

![原文配图](https://pbs.twimg.com/media/HNfpfigaoAAN4Z1.jpg)

安装方法也很简单，在Codex里输入这个指令就行了：

~~~
```
Read http://chatcut.io/chatgpt to install the ChatCut plugin and set up a new task for me.
```
~~~

注意，现在这个插件还没有在Codex插件市场上架，所以只能通过指令安装。

安装时，会弹出一个浏览器页面，让你注册登录ChatCut，这个直接用gmail邮箱就成。

初始账号一般会送20积分。我实测下来，只有涉及AI生成的部分需要消耗积分，其他素材处理、剪辑都不需要，所以相对来说还是比较耐用的。

2. Pexels API

这个是一个CC0无版权的照片和视频网站，有非常多优质的视频素材。而且它的API是免费的，随时可以调用。

![原文配图](https://pbs.twimg.com/media/HNftRThaUAA83ja.jpg)

申请地址：<https://www.pexels.com/api/>

申请流程很简单，注册一个账号，然后在后台生成API Key就可以了。

3. 微信读书Skill

这个Skill可以让你查询微信读书的书籍信息，还有各种书评、点评。

![原文配图](https://pbs.twimg.com/media/HNftJwLbAAAi1BO.jpg)

有了Skill，你就不需要费心想文案怎么写，让Codex看下别人是怎么写的，给你一个方案就好。

安装指令：

~~~
```
npx skills add Tencent/WeChatReading -g
```
~~~

安装完以后，登录你的微信读书账号，就可以查询书籍信息了。哦，也是免费的。

准备好这几个工具以后，你就可以同时解决素材问题、文案问题、剪辑问题。

剩下的，就是把它组合成一套完整的工作流。

![原文配图](https://pbs.twimg.com/media/HNfq9l8agAA4Xm6.jpg)

## 如何用Codex自动剪辑

工具都准备好，接下来就很简单了。

整个流程大概分为6个步骤，每个步骤都可以让Codex直接帮你完成。

第一步：确认书籍信息

比如你想做《超越百岁》这本书的带货视频，就直接跟Codex说：

~~~
```
请帮我查询《超越百岁》这本书在微信读书上的信息，包括：
- 书名、作者
- 简介、分类
- 评分、封面URL
- 章节目录

如果有多个版本或重名，让我选择一个。
```
~~~

Codex收到以后，会通过微信读书Skill搜索这本书，然后返回一些基本信息。比方说这是我搜索到的。

![原文配图](https://pbs.twimg.com/media/HNftBG_a0AAMW7M.jpg)

第二步：选择创作角度

拿到书籍信息后，就需要你去确定创作角度。

如果对这本书，你有自己的想法，你可以跟Codex说：

~~~
```
我想从"[你的角度]"这个角度讲这本书。

请帮我把这个想法整理成一个清晰的创作命题：
- 目标观众是谁
- 他们遇到什么问题
- 这本书能提供什么变化

如果这个角度不太合适，告诉我原因和改进建议。
```
~~~

如果没有想法也没关系，你可以跟Codex说：

~~~
```
请帮我从微信读书的公开点评里，找一个适合做短视频的创作角度。

要求：
- 收集20-40条有效点评
- 提取反复出现的痛点、具体处境、反直觉认识
- 给我2-3个候选角度
- 按受众代入感、与书的相关性、视觉化潜力综合判断
- 推荐一个最适合的角度，并说明理由
```
~~~

因为接入了微信读书Skill，所以你可以直接让Codex抓取这本书的公开点评，综合多个不同书评以后，给你推荐一个适合的视角。

![原文配图](https://pbs.twimg.com/media/HNftzbPbIAAhiID.jpg)

第三步：文案和分镜

视角确定以后，你就可以让AI去产出文案和分镜。你可以这样说：

~~~
```
基于刚才确认的角度，帮我写一个完整的口播文案。

文案结构：
- 固定开场："今天分享的是"
- 书名揭示：报出《书名》
- 正文：从观众的具体问题进入，给出书中可验证的认识或方法
- 收束：说明这本书适合谁，能帮助解决什么问题

文案要口语化，像朋友聊天一样。写完后先给我审核，确认后再继续生成素材。
```
~~~

有了文案以后，接下来你可以继续发这段提示词给Codex，让它生成分镜。

~~~
```
基于刚才的文案，帮我规划整组正文配图的分镜方案：

1. 先确定统一的视觉风格（比如：暗色电影感、写实人物、低饱和度）
2. 然后逐张规划：
   - 叙事功能（展示什么情境或情绪）
   - 景别（特写/近景/中景/全景）
   - 视角（平视/俯视/仰视/主观视角）
   - 构图（主体位置、画面重心）
   
要求：
- 相邻两张不能用相同景别和视角
- 整组镜头要有"建立空间→靠近情绪→观察细节→拉开距离→转折→收束"的视觉节奏
- 图中不生成字幕、书名或水印
```
~~~

这里说一下为什么要加入分镜呢？

因为 Codex 生图跟网页端是不一样的：

1. 网页端生图：你跟它说生成几张图，它可以在同一批次里面生成多张不同的图，所以图片看起来会很连贯。
1. Codex 生图：你让它生成多张图，它是分别调用生图功能去生成的。

因为每一张图都是独立的，这就产生了一个问题：它不知道其他图是什么样子的，所以可能会出现多张图都是相似视角和相似场景的情况。

所以，提前确定好分镜，你开始生图的时候，就不会出问题。

![原文配图](https://pbs.twimg.com/media/HNfrtmQawAAq0Gt.jpg)

第四步：画面准备

分镜方案确定以后，就可以开始准备画面素材了。

按照视频播放顺序，画面可以分为三个部分：

一是开场动画，用动态视频片段建立情绪。我搜索了一下，数据比较好的这些图书带货视频，基本上第一个画面都是动态的、偏情绪的画面。

这个可以通过Pexels API解决。

~~~
```
通过Pexels API搜索"book"关键词，找一个有书或阅读动作的竖屏视频作为开场，要求：
- 竖屏构图完整
- 轻微运动自然
- 中下部可以放双语字幕
- 无明显品牌文字或水印

找到后下载并保存到素材目录。
```
~~~

因为我想要第一个画面是和书有关的，所以我让他搜索的关键词是“book”。

但实际上，你可以让他先去分析文案，根据文案提炼出关键词再去搜索，这样就能得到更加匹配主题的开头画面。

二是书封轮播，就是图书封面配合节奏音效快速切换，最后一个卡点切到当前这本书的封面。

我原本在做的时候，其实是想要把正文部分生成的图片去给它轮切一遍，这样子的话，我就不需要再去找别的图片嘛。

但是后来我发现在微信读书skill里面，Codex是可以直接获取到书籍封面的，如果是这样子，这个部分用书籍封面效果就会更好一些。

三是正文配图，根据前面的分镜方案，逐张生成对应的配图。

因为前面已经规划好了每张图的景别、视角、构图，所以直接让Codex按照分镜方案生成图片就行。

![原文配图](https://pbs.twimg.com/media/HNfsKula8AEvmce.jpg)

第五步：ChatCut粗剪

素材都准备好以后，就可以让Codex在ChatCut里组装视频了。你可以这样说：

~~~
```
现在帮我在ChatCut里组装这个图书带货视频：

1. 创建一个新的ChatCut项目
2. 按顺序导入素材：
   - 开场视频片段（Pexels下载的）
   - 轮播用的图书封面
   - 正文配图
   
3. 配音：
   - 生成4个不同音色让我选择
   - 按文案的自然语义段生成配音
   - 根据配音的实际时长调整画面和字幕
   
4. BGM和音效：
   - 先搜索ChatCut音效库里的现有素材
   - BGM自动压低，不要盖住人声
   - 轮播部分配节奏音效
   
5. 字幕：
   - 中英文双语，中文为主，英文为辅
   - 两种语言用同一个时间区间
   - 避开主体、书封和界面安全区
   
6. 转场：
   - 轮播用硬切
   - 正文用短交叉溶解或淡入淡出

重要：直接操作时间线完成剪辑，不要调用ChatCut的AI Agent，避免消耗积分。

```
~~~

前面有说，如果你不使用ChatCut的AI功能的话，剪辑是完全免费的，唯一需要花费积分的地方就是配音。

但说实话挺便宜，我生成了几次配音也才花了1积分不到。

![原文配图](https://pbs.twimg.com/media/HNfszAlaoAAQ-_i.jpg)

不过在调用ChatCut时，一定要注意不要让codex去调用插件的Agent功能。

因为这个插件最近比较火，所以在调用的时候可能会有一点卡，会有点慢。有时候 Codex 就会去想别的解决方案。

我今天在迭代测试时就出现过这个问题。Codex直接去操控剪辑比较慢，然后它就去调用了ChatCut的AI功能，一下子把我十几积分全部干没了。 （血泪教训，虽然我能换号）

![原文配图](https://pbs.twimg.com/media/HNfskKOaoAE9tTS.jpg)

第六步：设置自动化

剪辑完成以后，剩下就没什么要做的了，无非就是在审核、微调，然后直接导出视频。

整个流程下来，从输入书名到拿到可编辑初稿，基本上15-30分钟就能搞定。

而且这里面一大半时间，是用在生成图片上，如果你换个速度快点的模型，可能10分钟都不到。

那下一步我们还可以做什么呢？

设置自动化啊。

跑通的流程，可以做成Skill。 （不知道怎么做Skill的，看看我前面的内容。）

有了Skill以后，你就有了自动化的基础。

比方说，你可以创建一个文档，把你每天想要分享的书放在里面，然后让 Codex 设置自动化，每天定时去读取这个文档。读取文档以后，它就知道今天要去做什么视频，然后让它去调用 skill，去完成这本书的带货视频。

而你要做的，就是每天审核一下带货视频，然后发布。

![原文配图](https://pbs.twimg.com/media/HNfsqlFboAAbpjd.jpg)

## 写在最后

怎么样，今天这期内容还算OK吧？

这种带货类的项目，真正的难点其实还不是后期的执行，而是前期的选品。

有了自动化以后，整个视频的剪辑你都可以放手让 Codex 去做，这样你就可以有更多的精力和心力去研究选品、观察市场。

看得多了以后，你会慢慢摸索出自己的内容风格，知道什么样的书好讲，什么样的角度容易打动人。

自然而然，你就更容易在这个项目上拿到结果。

而且说实话，图书带货方向的天花板其实挺高的。

我见过做得好的账号，一个月能搞几万块的佣金。这还是被动收入，视频发出去就一直在那，有人看就有人买。

所以，如果你想做副业搞钱，图书带货是一个很值得尝试的方向。
